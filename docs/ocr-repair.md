# OCR repair and verification

The original helper removed the MIME prefix before putting bytes in `base64Image`. OCR.space requires that field to include a data URI. The original analysis route also bypassed its native PDF helper, sent every PDF to OCR, logged extracted document contents, and substituted mock analysis when extraction failed. Those paths are removed.

The repaired helper sends multipart `file` bytes with a filename and accurate MIME type, with the key only in the server request header. Text files decode as UTF-8. PDF.js reads native text first. Sparse scanned pages are rendered individually to JPEG, then read by OCR.space. Digital page text and OCR page text are kept in their original order; the same page is not appended twice. Encrypted or corrupt documents, partial OCR results, unsupported files, empty extraction, missing/invalid keys, HTTP errors, quota errors, and timeouts return actionable errors. No filename-only live analysis or fallback mock is generated.

`FileUpload` accepts PDF/PNG/JPEG/TXT, retains a selected file after failure, and offers retry and manual text entry. It masks common Aadhaar, PAN, and phone patterns after extraction when enabled. This is pattern masking, not complete anonymization: the original scan reaches OCR.space before masking. The configured processors and this sequence are disclosed before submission.

Standalone uploads are limited to 2 MB so encoded JSON remains below common serverless request limits. OCR defaults to 1 MB per image, three scanned pages per extraction, engine 2, and English. PDFs with up to 40 pages of embedded text can be read locally. `OCR_MAX_FILE_BYTES`, `OCR_MAX_PAGES`, `OCR_SPACE_ENDPOINT`, `OCR_SPACE_ENGINE`, `OCR_SPACE_LANGUAGE`, and `OCR_TIMEOUT_MS` must match the account's plan. Use its issued HTTPS endpoint. The configurable language values are `eng`, `auto`, `chs`, and `cht`; engine 3 with `auto` can be selected for other languages, but those language results have not been verified in this change.

The OCR request defaults to 12 seconds and is capped at 20. Whole extraction is limited to 22 seconds. Analysis has a 55-second overall cancellation signal and runs inside a 60-second function budget. Cancelling the browser request aborts extraction/provider work. Standalone extraction is cached only in the active page instance and checked against the extraction configuration before reuse. The protected vault uses a durable cache tied to an authorized item version, its SHA-256, and parser/OCR settings. Original bytes remain separate from derivatives.

PDF.js and the canvas renderer are external server packages. Node 22.13+ is required by the installed PDF.js version; current local verification used Node 25. The worker, character maps, standard fonts and WASM files are included in function tracing. Windows paths use forward slashes for PDF.js resource URLs. Native rendering uses bundled PDF fonts instead of relying on fonts installed on the development computer. Actual Next runtime testing caught a webpack `require.resolve` rewrite that broke the worker path; the final code lets external PDF.js resolve its own installed worker.

Verification uses only synthetic fixtures in `tests/fixtures/ocr`. The deterministic suite checks digital/scanned/mixed PDFs, PNG/JPEG/TXT, page order, permission before external processing, encrypted/corrupt/spoofed files, multipart MIME/credentials, missing and invalid keys, partial provider errors, rate limits, timeout, masking, and extraction-setting changes. No test reads the repository's old `test.pdf` or prints extracted private text. `node test-ocr.js` runs deterministic tests; `node test-ocr.js --live` opts into the fixed synthetic live checks.

Live OCR.space verification succeeded using existing credentials for all five fixtures: digital PDF, scanned PDF, PNG, JPEG and a three-page mixed PDF. Each contained its expected synthetic marker. See `ocr-live-results.json`. The actual Next analysis endpoint also returned validated live analysis for digital and scanned PDFs and an explicit 422 for a corrupt PDF; see `analysis-route-results.json`. Deployment on the target Linux host, account-specific higher plan limits, and non-English OCR remain to be verified after setup.

Reference checked during repair: [OCR.space API documentation](https://ocr.space/ocrapi), particularly multipart inputs, MIME data URIs, error/partial exit codes, engine/language settings and plan limits.
